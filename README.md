# README - Music Library API (ระบบข้อมูลเพลง)

## 1. ภาพรวม

**Music Library API** เป็นระบบจัดการคลังเพลง ศิลปิน และเพลย์ลิสต์ รหัสนิสิต 67160005 (Pno 6) พัฒนาเพื่อแก้ปัญหาข้อมูลเพลงที่กระจัดกระจายและซ้ำซ้อน โดยเก็บข้อมูลในฐานข้อมูลเชิงสัมพันธ์ที่ผูกกันด้วย Foreign Key แล้วเปิดให้ระบบอื่นใช้ผ่าน RESTful API กลางชุดเดียว

**ความสามารถหลัก**

- จัดการศิลปิน เพลง และเพลย์ลิสต์ ครอบคลุม 8 Use Case (ค้นหาเพลง, ดูเพลงของศิลปิน, เพิ่มเพลง/ศิลปิน, สร้างเพลย์ลิสต์, เพิ่ม/นำเพลงออกจากเพลย์ลิสต์, ดูรายละเอียดเพลย์ลิสต์)
- ข้อมูลถูกต้องเสมอด้วย constraint ในฐานข้อมูล (`UNIQUE`, `FOREIGN KEY`, `CHECK`, `ON DELETE CASCADE`) และตรวจข้อมูลซ้ำอีกชั้นที่ API
- ดึงข้อมูลเสริมของเพลง (อัลบั้ม แนวเพลง รูปปก ตัวอย่างเสียง) จาก iTunes Search API โดยมี Timeout, Retry และ Fallback เมื่อ iTunes ล่ม
- ระบบแนะนำเพลงและสถิติภาพรวมของคลังเพลง
- หน้าเว็บสำหรับผู้ใช้ทั่วไป และเอกสาร API แบบโต้ตอบ (Swagger UI)
- ชุดทดสอบอัตโนมัติ (Jest + Supertest)

## 3. การไหลของข้อมูล

```
หน้าเว็บ (frontend/index.html)
        │  HTTP + JSON
        ▼
Express API  (src/index.js, พอร์ต 3100)
   │   1) ตรวจข้อมูลที่ส่งมา ──── ผิด ──► ตอบ 400
   │   2) ถามข้อมูลจาก MySQL ──── ซ้ำ/ไม่มีอยู่ ──► ตอบ 409 / 404
   ├──► MySQL  (Docker, พอร์ต 3307)          เก็บ artists, songs, playlists, playlist_songs
   ├──► src/services/recommendation-service.js ──► MySQL   (แนะนำเพลง, สถิติ)
   └──► src/services/external-api.js ──► iTunes API         (ข้อมูลเสริมของเพลง)
                                          └─ ล่ม/ช้า: timeout 3 วินาที ลองใหม่ 2 ครั้ง แล้วตอบค่า default

เบราว์เซอร์ ──► /api-docs  (Swagger UI อ่านเอกสารจาก openapi.yaml)
```

**ฐานข้อมูล 4 ตาราง** (ดูแผนภาพ ERD ที่ `erd.png`)

| ตาราง            | หน้าที่                                                | ความสัมพันธ์                                    |
| ---------------- | ------------------------------------------------------ | ----------------------------------------------- |
| `artists`        | ศิลปินหรือวงดนตรี (ชื่อห้ามซ้ำ)                        | 1 ศิลปิน มีได้หลายเพลง                           |
| `songs`          | เพลงในคลัง (ศิลปินเดียวกันห้ามมีเพลงชื่อซ้ำ)            | อ้างอิง `artists` ด้วย `artist_id`               |
| `playlists`      | เพลย์ลิสต์ (เจ้าของเดียวกันห้ามตั้งชื่อซ้ำ)             | -                                               |
| `playlist_songs` | ตารางเชื่อมระหว่างเพลย์ลิสต์กับเพลง (many-to-many)      | 1 เพลงอยู่ได้หลายเพลย์ลิสต์ แต่ห้ามซ้ำในเพลย์ลิสต์เดียวกัน |

## 5. การติดตั้งและรัน

```bash
docker compose up -d      # 1) เปิด MySQL (ครั้งแรกจะสร้างตารางและข้อมูลตัวอย่างให้เอง)
npm install               # 2) ติดตั้งไลบรารี
cp .env.example .env      # 3) สร้างไฟล์ตั้งค่า (ค่าตั้งต้นใช้ได้เลย)
npm start                 # 4) เปิด API ที่ http://localhost:3100
```

รอให้ MySQL พร้อมก่อนรัน `npm start` (ดูสถานะด้วย `docker compose ps` ต้องเป็น `healthy` ใช้เวลาประมาณ 30 วินาทีในครั้งแรก)

| ต้องการ                    | ทำอย่างไร                                                  |
| -------------------------- | ---------------------------------------------------------- |
| ใช้งานผ่านหน้าเว็บ         | เปิดไฟล์ `frontend/index.html` ด้วยเบราว์เซอร์              |
| ดูเอกสาร API และลองยิง     | เปิด `http://localhost:3100/api-docs` (ดูหัวข้อ 5.1)        |
| ตรวจว่าเซิร์ฟเวอร์ทำงาน     | เปิด `http://localhost:3100/health`                        |
| รีเซ็ตข้อมูลกลับเป็นตั้งต้น | `docker compose down -v` แล้ว `docker compose up -d`       |

> เมื่อแก้ไฟล์ในโปรเจกต์ ต้องหยุด (`Ctrl+C`) แล้วรัน `npm start` ใหม่ เซิร์ฟเวอร์จึงจะใช้โค้ดล่าสุด

### 5.1 เอกสาร API (Swagger UI)

เปิด **http://localhost:3100/api-docs** ในเบราว์เซอร์ (ต้องรัน `npm start` ก่อน) จะเห็นทุก endpoint แยกตามกลุ่ม Artists, Songs, Playlists, External, Microservices

วิธีลองยิงจากหน้านี้:

1. กดที่ endpoint ที่ต้องการให้ขยาย (เช่น `GET /api/v1/songs`)
2. กดปุ่ม **Try it out**
3. ใส่ค่าที่ต้องการ (เช่น `q`, `id` หรือ request body)
4. กดปุ่ม **Execute** แล้วดูผลที่ช่อง **Server response** (status code และ body จริงจากระบบ)

ในแต่ละ endpoint ดูได้ว่าส่งอะไรได้บ้าง และจะได้ response แบบไหนในแต่ละ status (200, 400, 404, 409 ฯลฯ) พร้อมตัวอย่าง ไฟล์ต้นทางของเอกสารคือ `openapi.yaml` และมี test (`npm test`) ตรวจว่าเอกสารตรงกับ route จริงทุกเส้น

## 7. Endpoint

ทุก path ขึ้นต้นด้วย `/api/v1` (ยกเว้น `/health`) รายละเอียด request/response ครบถ้วนอยู่ใน Swagger UI

| Method | Path                           | ทำอะไร                                          | Use Case |
| ------ | ------------------------------ | ----------------------------------------------- | -------- |
| GET    | `/health`                      | ตรวจว่าเซิร์ฟเวอร์ทำงานอยู่                     | -        |
| GET    | `/artists`                     | รายชื่อศิลปินทั้งหมด                            | -        |
| POST   | `/artists`                     | เพิ่มศิลปิน                                     | UC-04    |
| GET    | `/artists/:id/songs`           | เพลงทั้งหมดของศิลปิน                            | UC-02    |
| GET    | `/songs`                       | รายการเพลง (`?q=` ค้นหาชื่อเพลงหรือชื่อศิลปิน)  | UC-01    |
| GET    | `/songs/:id`                   | รายละเอียดเพลง                                  | -        |
| GET    | `/songs/:id/external-info`     | ข้อมูลเสริมจาก iTunes                           | -        |
| POST   | `/songs`                       | เพิ่มเพลง                                       | UC-03    |
| PUT    | `/songs/:id`                   | แก้ไขเพลง                                       | -        |
| DELETE | `/songs/:id`                   | ลบเพลง                                          | -        |
| GET    | `/playlists`                   | รายการเพลย์ลิสต์ (พร้อมจำนวนเพลง)               | -        |
| POST   | `/playlists`                   | สร้างเพลย์ลิสต์                                 | UC-05    |
| GET    | `/playlists/:id`               | รายละเอียดเพลย์ลิสต์ (รายการเพลงและเวลารวม)     | UC-08    |
| POST   | `/playlists/:id/songs`         | เพิ่มเพลงเข้าเพลย์ลิสต์                         | UC-06    |
| DELETE | `/playlists/:id/songs/:songId` | นำเพลงออกจากเพลย์ลิสต์                          | UC-07    |
| GET    | `/recommendations/songs/:id`   | แนะนำเพลง (`?limit=` 1-20 ค่าเริ่มต้น 5)        | -        |
| GET    | `/analytics/overview`          | สถิติภาพรวมของคลังเพลง                          | -        |

### 7.1 รูปแบบการตอบกลับ

- **สำเร็จ:** `{ "message": "...", "data": ... }` (ลบสำเร็จตอบ 204 ไม่มี body)
- **ผิดพลาด:** `{ "error": { "code": "...", "message": "..." } }` โดย `code` เป็นรหัสที่โปรแกรมตรวจสอบได้ เช่น `VALIDATION_ERROR`, `NOT_FOUND`, `DUPLICATE_SONG`

| Status | ความหมาย                                                                  |
| :----: | ------------------------------------------------------------------------- |
| 200    | สำเร็จ                                                                    |
| 201    | สร้างสำเร็จ                                                               |
| 204    | ลบสำเร็จ (ไม่มี body)                                                     |
| 400    | ข้อมูลที่ส่งมาไม่ถูกต้อง (ว่าง ชนิดผิด id ไม่ใช่จำนวนเต็มบวก JSON พัง)     |
| 404    | ไม่พบข้อมูลที่ระบุ                                                        |
| 409    | ข้อมูลซ้ำ (ศิลปิน เพลง เพลย์ลิสต์ หรือเพลงในเพลย์ลิสต์เดียวกัน)           |
| 500    | ข้อผิดพลาดภายในระบบ (ไม่เปิดเผยรายละเอียดภายในให้ผู้เรียก)                 |

## 8. เมื่อ iTunes ล่ม

`GET /songs/:id/external-info` ติดต่อ iTunes ด้วยกลไกป้องกันความล้มเหลว

| กลไก     | การทำงาน                                                                                         |
| -------- | ------------------------------------------------------------------------------------------------ |
| Timeout  | รอไม่เกิน 3 วินาทีต่อครั้ง                                                                       |
| Retry    | ลองใหม่ 2 ครั้ง (ยิงสูงสุด 3 ครั้ง) รอ 0.5 วินาที แล้ว 1 วินาที เฉพาะเน็ตหลุด, timeout และ 5xx     |
| Fallback | ถ้าลองครบแล้วยังไม่ได้ ตอบ HTTP 200 พร้อมค่า default และ `source: "fallback"` ข้อมูลหลักของเพลงยังครบ |

ผลทดสอบจริงของทั้ง 6 สถานการณ์อยู่ใน `failure-scenario-results.md` และจำลองความล้มเหลวเองได้ด้วย `scripts/mock-external-api.js`

## 12. แก้ปัญหาเบื้องต้น

| อาการ                                             | วิธีแก้                                                                        |
| ------------------------------------------------- | ------------------------------------------------------------------------------ |
| `npm start` แล้วต่อฐานข้อมูลไม่ได้                | เปิด Docker Desktop, รัน `docker compose up -d` และรอให้ `docker compose ps` เป็น `healthy` |
| พอร์ต 3100 ถูกใช้อยู่ (`EADDRINUSE`)               | หยุดโปรเซสเดิม หรือเปลี่ยน `PORT` ใน `.env` (และ `API_URL` ใน `frontend/index.html`) |

| `/api-docs` ตอบ 404                               | เซิร์ฟเวอร์ยังเป็นโค้ดรุ่นเก่า หยุดแล้วรัน `npm start` ใหม่                      |
| แก้ `schema.sql` แล้วฐานข้อมูลไม่เปลี่ยน           | สคริปต์รันเฉพาะตอนสร้างฐานข้อมูลครั้งแรก ให้รัน `docker compose down -v` แล้ว `docker compose up -d` |
| `npm test` ล้มเพราะต่อฐานข้อมูลไม่ได้              | เปิด MySQL ก่อน (`docker compose up -d`)                                       |
